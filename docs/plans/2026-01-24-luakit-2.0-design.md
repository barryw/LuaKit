# LuaKit 2.0 Design Document

**Date:** 2026-01-24
**Status:** Approved
**Breaking Changes:** Yes (major version bump)

## Overview

LuaKit 2.0 is a comprehensive update that addresses gaps identified through developer experience analysis. The goal is to make LuaKit cover all common Lua embedding use cases: game scripting, configuration, user automation, and plugin systems.

## Phases

### Phase 1: Quick Wins (Hours)

#### 1.1 Re-enable Disabled Tests

Restore and fix the following test files disabled during earlier development:

- `PropertyChangeTests.swift.disabled` → `.swift`
- `MacroTests.swift.disabled` → `.swift`
- `ArrayPropertyTests.swift.disabled` → `.swift`
- `ArrayElementAccessTests.swift.disabled` → `.swift`

- `ArrayProxyPublicAPITest.swift.disabled` → `.swift`

These were disabled because the `@LuaBridgeable` macro only recognized `public` members. This was fixed in the Swift 6 migration.

**Success criteria:** All restored tests pass with Swift 6 concurrency.

#### 1.2 Add Function Parameter Overloads (4-6 params)

Extend `LuaFunction` to support 4, 5, and 6 parameter closures:

```swift
public init<T1, T2, T3, T4, R>(_ closure: @escaping (T1, T2, T3, T4) -> R)
    where T1: LuaConvertible, T2: LuaConvertible, T3: LuaConvertible, T4: LuaConvertible

public init<T1, T2, T3, T4, T5, R>(_ closure: @escaping (T1, T2, T3, T4, T5) -> R)
    where T1: LuaConvertible, T2: LuaConvertible, T3: LuaConvertible,
          T4: LuaConvertible, T5: LuaConvertible

public init<T1, T2, T3, T4, T5, T6, R>(_ closure: @escaping (T1, T2, T3, T4, T5, T6) -> R)
    where T1: LuaConvertible, T2: LuaConvertible, T3: LuaConvertible,
          T4: LuaConvertible, T5: LuaConvertible, T6: LuaConvertible
```

Add corresponding `registerFunction` overloads on `LuaState`.

**Success criteria:** Can register and call functions with up to 6 typed parameters.

### Phase 2: Core API Improvements (Days)

#### 2.1 Call Lua Functions from Swift

**Problem:** No way to call a Lua function defined in Lua from Swift code.

**Solution:** New `LuaCallable` type:

```swift
public struct LuaCallable {
    /// Get a callable reference to a global Lua function
    public init(from state: LuaState, name: String) throws

    /// Get a callable reference to a function in a table (e.g., "Module.func")
    public init(from state: LuaState, path: String) throws

    /// Call with no arguments
    public func call<R: LuaConvertible>() throws -> R

    /// Call with arguments (overloads for 1-6 params)
    public func call<T1: LuaConvertible, R: LuaConvertible>(_ arg1: T1) throws -> R
    // ... up to 6 params

    /// Call with void return
    public func callVoid() throws
    public func callVoid<T1: LuaConvertible>(_ arg1: T1) throws
}

// Convenience on LuaState
extension LuaState {
    public func getFunction(_ name: String) throws -> LuaCallable
}
```

**Implementation notes:**
- Store Lua function reference in registry via `luaL_ref`
- On call: push function from registry, push args, `lua_pcall`, pull result
- Clean up registry reference on deinit

#### 2.2 Nested Collection Support

**Problem:** `[[String]]` and `[String: [Int]]` require manual `LuaValue` composition.

**Solution:** Extend `LuaConvertible` conformance to handle recursive types:

```swift
// Already works for [T] where T: LuaConvertible
// Ensure nested arrays work by recursive push/pull

extension Array: LuaConvertible where Element: LuaConvertible {
    public static func push(_ value: [Element], to L: OpaquePointer) {
        lua_createtable(L, Int32(value.count), 0)
        for (index, element) in value.enumerated() {
            Element.push(element, to: L)  // Recursive for nested arrays
            lua_rawseti(L, -2, lua_Integer(index + 1))
        }
    }

    public static func pull(from L: OpaquePointer, at index: Int32) -> [Element]? {
        // Recursive pull for nested arrays
    }
}

// Similar for Dictionary where Value: LuaConvertible
```

**Success criteria:**
```swift
let matrix: [[Int]] = [[1, 2], [3, 4]]
lua.globals["matrix"] = matrix
let back = lua.globals["matrix"] as? [[Int]]  // Works
```

#### 2.3 Table Iteration from Swift

**Problem:** No way to enumerate Lua table contents from Swift.

**Solution:** Make `LuaTable` conform to `Sequence`:

```swift
public struct LuaTable: Sequence {
    public struct Iterator: IteratorProtocol {
        public mutating func next() -> (key: LuaValue, value: LuaValue)?
    }

    public func makeIterator() -> Iterator

    // Convenience accessors
    public var keys: [LuaValue] { get }
    public var values: [LuaValue] { get }
    public var count: Int { get }

    // Typed access
    public subscript(key: String) -> LuaValue? { get set }
    public subscript(key: Int) -> LuaValue? { get set }
}

// Get table from globals
extension LuaGlobals {
    public subscript(table name: String) -> LuaTable? { get }
}
```

**Implementation:** Wrap `lua_next` in the iterator, keep table on stack during iteration.

### Phase 3: Advanced Features (Week+)

#### 3.1 Lua Function as Swift Callback

**Problem:** Can't pass a Lua function to a Swift method as a callback.

**Solution:** New `LuaCallback` type:

```swift
public final class LuaCallback: @unchecked Sendable {
    /// Call the Lua callback with arguments
    public func call<R: LuaConvertible>(_ args: any LuaConvertible...) throws -> R
    public func callVoid(_ args: any LuaConvertible...) throws

    /// Check if callback is still valid
    public var isValid: Bool { get }
}

// For use in @LuaBridgeable classes
@LuaBridgeable
class Player: LuaBridgeable {
    private var onDamageCallback: LuaCallback?

    func onDamage(_ callback: LuaCallback) {
        self.onDamageCallback = callback
    }

    func takeDamage(_ amount: Int) {
        try? onDamageCallback?.callVoid(amount)
    }
}
```

**Macro support:** The `@LuaBridgeable` macro must recognize `LuaCallback` parameters and generate appropriate bridging code.

#### 3.2 Coroutine Support

**Problem:** Lua coroutine library loads but no Swift wrapper exists.

**Solution:** New `LuaCoroutine` type:

```swift
public final class LuaCoroutine {
    public enum Status {
        case suspended
        case running
        case dead
    }

    /// Create coroutine from Lua code
    public init(from state: LuaState, code: String) throws

    /// Create coroutine from existing function
    public init(from callable: LuaCallable) throws

    /// Current status
    public var status: Status { get }

    /// Resume execution, returns yielded/returned value
    public func resume<R: LuaConvertible>() throws -> R
    public func resume<T1: LuaConvertible, R: LuaConvertible>(_ arg: T1) throws -> R
}

// Usage
let coro = try lua.createCoroutine("""
    for i = 1, 5 do
        coroutine.yield(i * 10)
    end
    return "done"
""")

while coro.status == .suspended {
    let value: Int = try coro.resume()
    print(value)  // 10, 20, 30, 40, 50
}
```

#### 3.3 Table Serialization

**Problem:** No built-in way to convert tables to/from JSON or Codable.

**Solution:** Extensions for serialization:

```swift
extension LuaTable {
    /// Convert to JSON string
    public func toJSON(prettyPrint: Bool = false) throws -> String

    /// Convert to dictionary for Codable
    public func toDictionary() -> [String: Any]
}

extension LuaState {
    /// Load JSON as a Lua table
    public func loadJSON(_ json: String, as name: String) throws

    /// Load JSON data
    public func loadJSON(_ data: Data, as name: String) throws
}

// Codable support
extension LuaGlobals {
    public func decode<T: Decodable>(_ name: String, as type: T.Type) throws -> T
    public func encode<T: Encodable>(_ value: T, as name: String) throws
}
```

### Phase 4: API Cleanup

#### 4.1 Naming Consistency

| Current (1.x) | New (2.0) |
|---------------|-----------|
| `executeReturning(_:as:)` | `execute(_:returning:)` |
| `setPrintHandler(_:)` | `onPrint(_:)` |
| `setOutputHandler(_:)` | Remove (duplicate) |
| `registerFunction(_:_:)` | `register(function:as:)` |
| `LuaEnumBridgeable` | `LuaBridgeableEnum` |
| `registerEnum(_:as:)` | `register(enum:as:)` |

#### 4.2 Error Consolidation

Merge `LuaErrorContext` into `LuaError`:

```swift
public enum LuaError: LocalizedError {
    case memoryAllocation
    case syntax(message: String, line: Int?, hint: String?)
    case runtime(message: String, stackTrace: String?)
    case typeMismatch(expected: String, got: String, context: String?)
    case invalidArgument(function: String, parameter: String?, reason: String)
    case validation(property: String, value: String, reason: String)
    case callbackInvalid(reason: String)
}
```

#### 4.3 Hide Implementation Details

- Remove all `OpaquePointer` from public API
- Re-export necessary Lua constants from LuaKit (no `import Lua` needed)
- Make `LuaState` the sole public entry point
- Hide `LuaClosureStorage`, `LuaKitRegistry` internals

## Migration Guide (1.x → 2.0)

```swift
// Before (1.x)
import Lua
import LuaKit

let result = try lua.executeReturning("return 42", as: Int.self)
lua.setPrintHandler { print($0) }
lua.registerFunction("add") { (a: Int, b: Int) in a + b }

// After (2.0)
import LuaKit  // No more import Lua needed

let result: Int = try lua.execute("return 42", returning: Int.self)
lua.onPrint { print($0) }
lua.register(function: { (a: Int, b: Int) in a + b }, as: "add")
```

## Implementation Order

1. **Phase 1.1** - Re-enable tests (validates existing code)
2. **Phase 1.2** - Add parameter overloads (low risk)
3. **Phase 2.1** - LuaCallable (foundational for Phase 3)
4. **Phase 2.2** - Nested collections (extend existing code)
5. **Phase 2.3** - Table iteration (new but isolated)
6. **Phase 3.1** - LuaCallback (builds on LuaCallable)
7. **Phase 3.2** - Coroutines (independent feature)
8. **Phase 3.3** - Serialization (independent feature)
9. **Phase 4** - API cleanup (do last, affects everything)
